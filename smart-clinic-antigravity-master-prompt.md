## 3. VISUAL IDENTITY SYSTEM

### 3.1 Visual Direction: Warm Luxury

The site uses a **Warm Luxury** direction — beige, cream, and champagne tones, NOT the cold clinical blue/white that every generic clinic website defaults to, and NOT dark/cinematic. Warmth signals humanity and boutique comfort; the AI/technology elements provide the modern edge that keeps it from feeling like a spa.

### 3.2 Color Palette — White + Champagne Gold

- **Primary background:** Warm off-white / ivory (not pure `#FFFFFF` — something like `#FAF7F2` or `#F8F4EE`) — pure white feels clinical and cold; ivory feels considered.
- **Champagne Gold:** A muted, sophisticated metallic-adjacent gold (not bright yellow-gold — think `#B8975E` to `#C9A876` range), used **sparingly**: hairline dividers, hover underlines, icon accents, the AI-analysis motif, small CTA accents. Gold is a whisper, not a shout — never fill large areas with it.
- **Deep neutral (text/anchor color):** A near-black warm charcoal (e.g. `#2B2723`) rather than pure black — softer, warmer, still highly legible.
- **Secondary neutral / card backgrounds:** A slightly deeper cream/sand tone (e.g. `#F0E9DF`) to create subtle layering without introducing a new hue.
- **Accent for AI/tech touches only:** A very restrained, desaturated warm bronze or soft gold-glow used only in the AI Skin Analysis page and technology diagrams — never a bright neon or saturated blue (which would break the warm-luxury feeling).

Rule: **at least 80% of every viewport should be negative space or imagery** — color is used as punctuation, not paint.

### 3.3 Typography

Use an **editorial, fashion-magazine-grade type system** — this is the single highest-leverage design decision on this site.

- **Display/Headline typeface:** An elegant high-contrast serif (e.g. a Didone or transitional serif — visually similar to Canela, Freight Display, GT Sectra, or Playfair Display if using Google Fonts). Used for H1/H2, large and generously letter-spaced, often in title case or elegant sentence case — never all-caps for long headlines (short eyebrow labels may use small tracked caps).
- **Body/UI typeface:** A clean, refined sans-serif with excellent legibility at small sizes (e.g. similar to Söhne, Neue Montreal, or Inter as a fallback) for paragraphs, navigation, buttons, and forms.
- **Hierarchy:**
  - H1 (hero): extremely large (clamp between ~48px mobile and ~96–120px desktop), serif, tight leading, generous letter-spacing on any all-caps eyebrow text above it.
  - H2 (section titles): large serif, editorial, often paired with a small tracked-caps eyebrow label above (e.g. "TECHNOLOGY" in gold, tracked, small).
  - Body copy: sans-serif, comfortable line-height (1.6–1.8), constrained line length (max ~65–75 characters) — never full-bleed paragraph text.
  - Never use a default system font. Never use generic bold sans-serif for headlines — this is the #1 signal of a template site.

### 3.4 Spacing & Layout Principles

- **Extremely generous whitespace.** Section vertical padding should feel closer to a design portfolio or fashion site than a business website — think 120–200px of vertical breathing room between major sections on desktop, scaling down proportionally on mobile but never cramped.
- Use an asymmetric, editorial grid in places (e.g. large image on one side, generous margin and small text block on the other) rather than everything centered and boxed.
- Avoid symmetrical "3-icon-cards-in-a-row" SaaS-template layouts as the default pattern. Vary rhythm: full-bleed image sections, alternating text/image, occasional full-width typographic statements with no imagery at all.
- Container max-width should be generous but not full-bleed for text (~1200–1320px), while imagery and hero sections can go full-bleed edge to edge.

### 3.5 Iconography

**No icons unless they genuinely improve comprehension.** Do not use generic medical/UI icon packs (syringes, checkmarks-in-circles, generic clocks). Where an icon is truly necessary (e.g. clinic hours, phone, location in contact section), use a single custom-drawn, thin-line, minimal icon set consistent with the gold/charcoal palette — never a colorful flat-icon library.

### 3.6 Imagery & Photography Direction

- Soft, natural, diffused lighting — never harsh clinical fluorescent lighting, never oversaturated "stock medical photo" look.
- Warm, neutral tones consistent with the champagne/ivory palette.
- Every image should look like it belongs in a **luxury skincare campaign**, not a healthcare brochure — close-up skin textures, elegant portraiture, negative space around subjects, editorial composition (subject off-center, generous crop).
- No generic stock photos of random smiling doctors in white coats against a blue background. No stock "diverse group of doctors with arms crossed" imagery.
- Since only doctor photography is confirmed as available for now (per content notes below), **use elegant, minimal placeholder treatment** for all other imagery: large soft gradient/texture blocks in the palette tones, subtle abstract AI-inspired line patterns, or tasteful cropped macro-texture placeholders (skin texture, light, fabric) — never a broken-image icon or a generic gray box. Structure the code so real photography can be dropped in later without any layout changes.
- Before/after and gallery imagery: build the structure and section but keep it **disabled/hidden** (commented out or feature-flagged) since patient consent is not yet available — see Section 8.7.

### 3.7 Animation & Micro-interaction Standards

Framer-quality, never flashy:
- Subtle fade-and-rise on scroll for section content (short duration, ~400–600ms, eased, staggered slightly for groups of elements). No bouncing, no spinning, no over-the-top parallax.
- Smooth, refined hover states: gold underline that draws in on link hover, subtle scale (1.02–1.03) and shadow lift on cards, never harsh color inversion.
- Page transitions and section reveals should feel like turning the page of a beautifully printed magazine — smooth easing curves (e.g. `cubic-bezier(0.22, 1, 0.36, 1)`), not linear or bouncy.
- Cursor-aware subtle interactions are welcome on desktop (e.g. gentle image parallax on mouse move in the hero) but must degrade gracefully and never be required for comprehension.
- Respect `prefers-reduced-motion` — disable non-essential motion for users who request it.

## 4. THINGS TO EXPLICITLY AVOID

Antigravity (and any AI website builder) defaults to these patterns unless explicitly told not to. Do **none** of the following:

- Generic healthcare/template layouts (hero + 3 icon cards + testimonial carousel + footer, repeated per section)
- Stock-looking doctor cards (circular photo, name, one-line title, social icons in a row) — doctor presentation must feel like an editorial profile, not a team-page template
- Cramped spacing, small margins, boxed-in sections
- Bright clinical blue, teal, or mint green anywhere in the palette
- All-caps bold sans-serif headlines
- Icon soup — icons on every bullet point
- Rotating hero carousels/sliders
- Floating trust badges, review-count popups, "X people booked today" urgency widgets
- Countdown timers or artificial scarcity
- Sales-oriented CTA language ("Book Now!!", "Limited Spots!", "Don't Miss Out")
- Auto-playing background video with generic stock clinic B-roll
- Chatbot-style pop-ups that appear unprompted
- Any layout that looks identical to a Wix/Squarespace medical spa template

## 10. TECHNICAL IMPLEMENTATION GUIDANCE FOR ANTIGRAVITY

### 10.1 Stack
- Build as a modern static/SPA front-end suitable for Antigravity's build approach (React-based component architecture recommended: componentize per section listed in Sections 6–8, with a shared design-token file for the color palette, type scale, and spacing scale defined in Section 3 so the entire site stays visually consistent and easy to theme).
- Centralize the design system as reusable tokens/variables (colors, font families, spacing scale, border-radius, shadow style, transition easing curve) rather than hardcoding values per component — this keeps the "warm luxury" identity consistent site-wide and easy to adjust later.
- Structure content (doctor bios, treatments, FAQs) as data objects/arrays rather than hardcoded JSX where practical, so content can be updated without touching layout code.

### 10.2 Responsive Design
- Mobile experience must receive **equal design attention**, not a compressed afterthought. Re-think each section's composition for mobile rather than simply stacking desktop columns — e.g. the asymmetric two-column About section becomes a full-width image with the text flowing beneath, still with generous padding and editorial type scale (reduced but still confident, not shrunk to generic mobile-web sizes).
- Typography should use fluid/clamp-based sizing so headlines scale smoothly between breakpoints rather than jumping abruptly.
- Touch targets (nav, CTA buttons, accordion FAQ items) must be comfortably sized for mobile tapping.
- Test the Book Consultation modal/sheet specifically on mobile — it should feel like a natural slide-up sheet, not a shrunk desktop modal.

### 10.3 Performance
- Lazy-load below-the-fold imagery.
- Keep animation libraries lightweight; prefer CSS transitions/`Intersection Observer`-driven reveal classes over heavy animation dependencies where possible.
- Optimize for fast first paint on the hero — the hero image is the first impression and must not cause layout shift or a slow, janky load.

### 10.4 Accessibility
- Maintain sufficient color contrast between the warm ivory background, charcoal text, and gold accents — gold-on-ivory must never be used for body text (reserve gold for accents, dividers, hover states, and short labels only).
